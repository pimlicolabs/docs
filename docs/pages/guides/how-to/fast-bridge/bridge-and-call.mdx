# How to bridge tokens and call contracts on the destination chain

This guide shows you how to bridge a user's tokens with Pimlico Fast Bridge and call contracts with them on the destination chain in the same request, for example to deposit into a vault. The bridge delivers the tokens to its `multicaller` address, which runs your calls in order as `msg.sender`. To only deliver the tokens to an address, see [How to bridge tokens between chains with Fast Bridge](/guides/how-to/fast-bridge/bridge-tokens).

## Prerequisites

- A Pimlico API key. [Create one](/guides/create-api-key).
- An EOA holding a [supported token](/references/fast-bridge#supported-chains-and-tokens) on the origin chain, within the per-request limit. The steps use USDC on Base.
- An EVM destination chain. Calls can't run on Solana.

Create the user's account and a helper that calls the Fast Bridge API with your API key, then fetch `approvalAddress` and `multicaller` from [`GET /addresses`](/references/fast-bridge/endpoints#get-addresses). The addresses don't change, so fetch them once and reuse them for every request.

If a call would revert, the request is rejected with `CALLS_SIMULATION_REVERTED` before any funds move. If you already know the gas your calls need, pass it as `gasLimit` to skip the estimate.

:::warning
Make your calls spend or forward the full `amountOut`. The bridge doesn't return anything left on `multicaller` after your calls run.
:::

### Check that the calls ran

Poll [`GET /status/{requestId}`](/references/fast-bridge/endpoints#get-statusrequestid) until the request is final. If a call reverts on the destination chain, the destination leg is `reverted` with a `CALLS_REVERTED` [error](/references/fast-bridge/errors#destination-leg) that names the call.
