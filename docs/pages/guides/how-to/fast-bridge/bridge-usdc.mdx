# How to bridge USDC between chains with Fast Bridge

This guide shows you how to move a user's USDC from one chain to another with Pimlico Fast Bridge. The user signs one token authorization and holds no gas on either chain. The example bridges native USDC from Base to Arbitrum; to bridge from BSC, see [How to bridge USDC from BSC with Permit2](/guides/how-to/fast-bridge/bridge-with-permit2).

## Prerequisites

- A Pimlico API key. [Create one](/guides/create-api-key).
- An EOA holding USDC on the origin chain, within the [per-request limit](/references/fast-bridge#supported-chains-and-tokens).

### Sign a ReceiveWithAuthorization

Have the user sign an EIP-3009 `ReceiveWithAuthorization` for the amount to bridge, with `to` set to `approvalAddress` and a random 32-byte nonce. Give it a `validBefore` a few minutes ahead: the origin pull must land before it.

### Send the request

Send the authorization to [`POST /execute/sync`](/references/fast-bridge/endpoints#post-executesync) with the route and the `recipient` on the destination chain. If you'd rather not hold the connection open, send it to [`POST /execute`](/references/fast-bridge/endpoints#post-execute) instead, which answers `202` as soon as the request is accepted.

If the request is rejected, nothing has moved: fix what the [error code](/references/fast-bridge/errors) names, and sign a new authorization if it was used or has expired.

### Check that the USDC arrived

If the response is still `pending`, poll [`GET /status/{requestId}`](/references/fast-bridge/endpoints#get-statusrequestid) until it isn't, or until the destination leg is `reverted` or `failed`.
