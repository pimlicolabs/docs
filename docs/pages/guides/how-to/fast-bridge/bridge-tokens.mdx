# How to bridge tokens between chains with Fast Bridge

This guide shows you how to move a user's tokens from one chain to another with Pimlico Fast Bridge. The user signs one token authorization and holds no gas on either chain. To spend the tokens on the destination chain in the same request, see [How to bridge tokens and call contracts on the destination chain](/guides/how-to/fast-bridge/bridge-and-call).

## Prerequisites

- A Pimlico API key with Fast Bridge enabled. [Create one](/guides/create-api-key), then ask [support@pimlico.io](mailto:support@pimlico.io) to enable Fast Bridge for it.
- An EOA holding a [supported token](/references/fast-bridge#supported-chains-and-tokens) on the origin chain, within the per-request limit. The steps use USDC on Base.

### Sign a ReceiveWithAuthorization

Have the user sign an EIP-3009 `ReceiveWithAuthorization` for the amount to bridge, with `to` set to the origin chain's `approvalAddress` and a random 32-byte nonce. Give it a `validBefore` a few minutes ahead: the origin pull must land before it. If the origin token has no EIP-3009 support, sign a Permit2 transfer instead, as in [Bridge from BSC](#bridge-from-bsc).

## If the response is still pending

A `pending` response means one of two things:

- The delivery failed after the origin leg confirmed. The destination leg is `reverted` or `failed` with an `error`, and the tokens stay in the bridge's reserve. See [leg errors](/references/fast-bridge/errors#destination-leg).
- The `timeout` passed first. Poll [`GET /status/{requestId}`](/references/fast-bridge/endpoints#get-statusrequestid) until the request is final. Do the same if you sent the request to [`POST /execute`](/references/fast-bridge/endpoints#post-execute), which responds `202` as soon as the request is accepted.

## Bridge from BSC

Binance-Peg USDC on BSC has no EIP-3009 support, so have the user sign a [Permit2](https://github.com/Uniswap/permit2) `PermitTransferFrom` with `spender` set to BSC's `approvalAddress`, and send it as a `permit2` authorization. The token has 18 decimals, so parse the amount with 18.

The user must first approve the Permit2 contract (`0x000000000022D473030F116dDEE9F6B43aC78BA3`) for the token, once, in a transaction paid in BNB. Without it, the request is rejected with `INSUFFICIENT_ALLOWANCE`.
