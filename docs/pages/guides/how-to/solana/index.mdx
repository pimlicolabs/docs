# Solana Sponsorships

Solana Sponsorships lets you sponsor the transaction fees for your users on Solana, so they can transact without holding SOL.

## Verifying Paymaster

You pay the fee for your users. The only requirement is that the transaction simulates successfully and does not call a blocked program.

[Use the Verifying Paymaster →](/guides/how-to/solana/verifying-sponsorship)

## Sponsor with USDC or other SPL tokens

Your users pay the fee in USDC or another SPL token. The paymaster pays the SOL fee and is repaid with a token transfer in the same transaction.

[Sponsor with USDC or other SPL tokens →](/guides/how-to/solana/token-sponsorship)

## Quick start

```sh
npm install @pimlico/solana @solana/kit
```

```ts
import { createSolanaPaymaster } from "@pimlico/solana";
import { createSolanaRpc } from "@solana/kit";

const solanaRpc = createSolanaRpc("https://api.mainnet-beta.solana.com");

const paymaster = createSolanaPaymaster({
    paymasterUrl: "https://solana.pimlico.io/v1/rpc?apikey=YOUR_API_KEY",
    solanaRpc,
});

const signature = await paymaster.sendTransaction({
    instructions,
    signers: [user],
    sponsorship: { type: "verifying" }, // or { type: "token", mint: usdcMint }
});

await paymaster.waitForTransaction(signature);
```

## How it works

1. The SDK sets the paymaster as the fee payer of your transaction and signs it with your user's key.
2. In token mode it also appends a token transfer to the paymaster's vault for the fee.
3. The paymaster validates the transaction, signs it as fee payer, broadcasts it, and returns the signature.
4. `waitForTransaction` polls until the transaction is `finalized`, `failed`, or `expired`.

The signature is a normal Solana transaction signature, so you can look it up on any explorer.

For wallets like Phantom that sign for you, use `prepareTransaction` and `sponsorTransaction` instead of `sendTransaction`. Both guides show how.

:::info
The SDK wraps a JSON-RPC API. If you'd rather call it directly, see the [endpoint reference](/references/paymaster/solana/endpoints).
:::

## Requirements

- Legacy and v0 transactions are supported, including lookup tables.
- Durable nonce transactions are not supported.
- The paymaster may only be the fee payer. An instruction that references it is rejected.
- A short list of programs can't be sponsored.
- One transaction per request.
