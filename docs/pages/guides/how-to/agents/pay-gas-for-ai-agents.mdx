# How to pay gas fees for an AI agent's wallet

This guide shows you how to pay gas for an AI agent that sends transactions from its own wallet, without funding the agent with ETH. Your app sponsors the agent's gas through a **sponsorship policy** with hard spending limits, and once a limit is reached the agent pays gas from its own USDC through the **ERC-20 Paymaster**. If the agent acts on behalf of a user's existing wallet instead of its own, see [How to send USDC without ETH for gas](/guides/how-to/payments/send-usdc-without-eth).

This guide uses Base. The same code works on any [supported chain](/guides/supported-chains) once you change the chain, the RPC URL and the USDC address.

## Prerequisites

- A Pimlico API key on a plan that includes mainnets. [Create one](/guides/create-api-key).
- A signer for the agent from a key management service or server wallet (Turnkey, Privy, Fireblocks, a cloud KMS) that you can load as a viem `LocalAccount`. See [signers](/guides/how-to/signers).
- An agent framework that lets you register your own tools.



## Steps

::::steps

### Create a sponsorship policy for your agents

In the [Pimlico dashboard](https://dashboard.pimlico.io/sponsorship-policies), create a policy for Base and set:

- a **global limit**, the most you will spend on agent gas in total,
- a **per-user limit**, which applies to each agent's account address, and
- a **per-user-operation limit**, so one runaway call can't use the whole budget.

Copy the policy ID (`sp_…`). To decide sponsorship based on what the agent is calling, add a [sponsorship policy webhook](/guides/how-to/sponsorship-policies/webhook) as well.

## Run many agents

Create one smart account per agent, each from its own signer. The per-user limit in your policy then applies to each agent separately. If one agent sends several transactions at once, give each its own nonce key, as described in [How to send multiple user operations in parallel](/guides/how-to/parallel-transactions).

## Use an agent's existing EOA

If the agent already has an EOA with funds in it, keep its address with EIP-7702: replace `toSafeSmartAccount` with `to7702SimpleSmartAccount` (EntryPoint 0.8) and attach a signed authorization to the first user operation. See the [EIP-7702 quickstart](/guides/eip7702/demo).
