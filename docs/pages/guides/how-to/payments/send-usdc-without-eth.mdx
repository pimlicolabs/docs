# How to send USDC without ETH for gas

This guide shows you how to let users send USDC from an account that holds no ETH, with either the user or your app paying the network fee. If the user's USDC is in an EOA, also follow [Send from an existing EOA with EIP-7702](#send-from-an-existing-eoa-with-eip-7702).

This guide uses Base. For other chains, check the [supported tokens](/references/paymaster/erc20-paymaster/supported-tokens). To try it on Base Sepolia first, follow [Tutorial 2](/guides/tutorials/tutorial-2), which uses testnet USDC from the Circle faucet.

### Create the clients

The Pimlico client is both the bundler and the paymaster. Passing `prepareUserOperationForErc20Paymaster` as the smart account client's `prepareUserOperation` makes it add the paymaster approval whenever `paymasterContext` contains a `token`.

The account address is counterfactual: it's known before the account is deployed, and the account is deployed by its first user operation. Send the user's USDC to `account.address`.

### Show the fee before the user confirms

Prepare the user operation with the USDC transfer and `paymasterContext: { token: USDC }`, then convert its maximum gas cost into USDC with `estimateErc20PaymasterCost`. `costInToken` is in USDC base units (6 decimals) and `costInUsd` always has 6 decimals.

```ts

```

The estimate is the most the paymaster can charge for this user operation. The amount actually charged is computed from the gas used, so it's usually lower.

### Check the balance covers the amount and the fee

The paymaster collects USDC from the sender after the transfer executes. If the account sends its entire balance, nothing is left for the fee and the user operation fails simulation. For a "send max" button, send the balance minus the fee estimate.

Check `receipt.success` before you show the transfer as sent. If the account's allowance for the paymaster is too low, the user operation approves the maximum fee before the transfer, in the same batch, so the user still signs once.

## Notes

<WhenFeePayer is="user">

- **Approval strategy**: `prepareUserOperationForErc20Paymaster` approves only the maximum fee of each user operation. If you prefer a one-time unlimited approval, see [using the ERC-20 Paymaster with unlimited approvals](/guides/how-to/erc20-paymaster/how-to/use-paymaster-with-unlimited-approval).
- **Sponsorship window**: an ERC-20 Paymaster sponsorship is valid for 10 minutes, so prepare and send the user operation in the same session.
- **API keys**: in a client app, route Pimlico requests through your backend instead of embedding the key ([guide](/guides/how-to/security/protect-api-keys)).

</WhenFeePayer>
