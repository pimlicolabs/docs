# How to let users swap on Base without ETH

This guide shows you how to let users swap tokens on Base without holding ETH, by sending the token approval and the swap as **one ERC-4337 user operation** with gas paid in USDC through Pimlico's **ERC-20 Paymaster**, or [sponsored by your app](#sponsor-the-swap-instead). The user signs once, and the approval and the swap either both execute or both revert. Get the swap itself from the DEX aggregator or router you already use; Pimlico doesn't quote or route swaps.

### Create the clients

If your users have an EOA with funds in it, use `to7702SimpleSmartAccount` (EntryPoint 0.8), as this example does, so the account keeps the user's EOA address. If they have ERC-4337 smart accounts, create them with `toSafeSmartAccount` or `toSimpleSmartAccount` instead, and skip the authorization in the send step. ```ts


If you offer a "sell max" button, cap the sell amount at the balance minus this fee. The ERC-20 Paymaster collects its fee *after* the calls execute, so a quote for the full balance fails simulation: nothing is left to pay the fee. If the allowance is too low, the user operation also approves the paymaster's maximum fee before the swap, in the same batch.

### Send the user operation

The first user operation from an EOA that isn't delegated yet must carry a signed EIP-7702 authorization. After that, the EOA's code points at the Simple account implementation and the authorization can be omitted.

## Sponsor the swap instead

To make swaps free for users, sponsor them with the verifying paymaster. Pass a `sponsorshipPolicyId` instead of a `token`; the ERC-20 Paymaster override then does nothing, and no paymaster approval is added.

```ts
// [!include ~/snippets/payments/swap-without-eth.ts:sponsored]
```

Give the policy a per-user operation count or spending limit, a per-user-operation cap, and `chain_ids.allowlist: [8453]` so it only sponsors on Base. See [How to use sponsorship policies](/guides/how-to/sponsorship-policies), and use a [webhook](/guides/how-to/sponsorship-policies/webhook) if you only want to sponsor calls to your router.

## Notes

- **Slippage**: set it in your aggregator's quote. The minimum output amount is encoded in the router calldata, and batching doesn't change it.
- **Other chains or EntryPoints**: check the token is listed in [supported tokens](/references/paymaster/erc20-paymaster/supported-tokens) before you pass it as `paymasterContext.token`.
- **Paying gas in another token**: if the user is selling a different supported token, pass that token in `paymasterContext.token` instead. The same balance rule applies.
- **External wallets** such as browser extensions usually won't let your app sign an EIP-7702 authorization for them. If the wallet supports EIP-5792 `wallet_sendCalls` with a paymaster service, you can send the same approve + swap calls through it. See [sponsoring transactions for external wallets](/guides/eip7702/external).
- **API keys**: don't ship your Pimlico API key in a client app; proxy requests through your backend ([guide](/guides/how-to/security/protect-api-keys)).
