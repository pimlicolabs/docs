# How to accept USDC at checkout without customers needing ETH for gas

This guide shows you how to accept USDC at checkout when your customers pay from their own wallet and hold no ETH for gas. The customer signs a USDC permit ([EIP-2612](https://eips.ethereum.org/EIPS/eip-2612)) instead of sending a transaction. Your server's smart account then uses the permit to move the USDC to your treasury, with gas sponsored by Pimlico's **verifying paymaster**. If you control your users' wallets, see [How to send USDC without ETH for gas](/guides/how-to/payments/send-usdc-without-eth) instead.

This guide uses Base and its native USDC (`0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913`). To use another chain, see [Accept payments on another chain](#accept-payments-on-another-chain).

## Prerequisites

- A Pimlico API key on a plan that includes mainnets. [Create one](/guides/create-api-key).

## Settle payments in parallel

If several settlements may be in flight at once, give each one its own nonce key so they don't wait on each other. See [How to send multiple user operations in parallel](/guides/how-to/parallel-transactions). Before your first parallel settlement, deploy the server account with one user operation, as in [How to send USDC payouts to thousands of recipients](/guides/how-to/payments/payouts).

## Refund a customer

To refund an order, send USDC from your treasury back to the customer. If you set `MERCHANT_TREASURY` to `serverAccount.address`, send the refund as a `transfer` call from the server client, and Pimlico sponsors it the same way.

## Accept payments on another chain

Change the chain, the RPC URL and the USDC address. Then read `name()` and `version()` from that chain's USDC contract and use them in the typed data `domain`. If they don't match, the signature is invalid and settlement reverts. The same flow works for any token that implements EIP-2612 `permit`.

## Notes

- If the customer pays from a smart contract wallet, keep the `bytes signature` overload of `permit` used here. USDC checks it with ERC-1271, which only works once the customer's wallet is deployed.
- If you keep the server account's owner key in a key management service (Turnkey, Fireblocks, Dfns, a cloud KMS), pass its viem `LocalAccount` as the `owner` instead of `privateKeyToAccount`.
- If you don't want to host a private key on your server for this, reach out to [support@pimlico.io](mailto:support@pimlico.io).
