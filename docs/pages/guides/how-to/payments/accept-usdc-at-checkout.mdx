# How to accept USDC at checkout without customers needing ETH for gas

This guide shows you how to accept USDC at checkout when your customers pay from their own wallet and hold no ETH for gas. The customer signs a USDC payment authorization ([EIP-3009](https://eips.ethereum.org/EIPS/eip-3009)) instead of sending a transaction, and your backend settles it from your merchant smart account with gas sponsored by Pimlico's **verifying paymaster**. If you control your users' wallets, see [How to send USDC without ETH for gas](/guides/how-to/payments/send-usdc-without-eth) instead.

This guide uses Base and its native USDC (`0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913`). To use another chain, see [Accept payments on another chain](#accept-payments-on-another-chain).

## Prerequisites

- A Pimlico API key on a plan that includes mainnets. [Create one](/guides/create-api-key).
- A signer for your merchant account from a key management service (Turnkey, Fireblocks, Dfns, a cloud KMS) that you can load as a viem `LocalAccount`. See [signers](/guides/how-to/signers).

### Ask the customer to sign

Send the request to the browser and ask the customer's wallet to sign it with `signTypedData`. The wallet shows a USDC signature request rather than a transaction, so it works with no ETH in the wallet.

Send the signature back to your backend with the order ID.


If one authorization in the batch is invalid, the whole user operation reverts. Check each customer's balance and `validBefore` before you add the payment to the batch.

## Settle payments in parallel

If several settlements may be in flight at once, give each one its own nonce key so they don't wait on each other. See [How to send multiple user operations in parallel](/guides/how-to/parallel-transactions). Before your first parallel settlement, deploy the merchant Safe with one user operation, as in [How to send USDC payouts to thousands of recipients](/guides/how-to/payments/payouts).

## Accept payments on another chain

Change the chain, the RPC URL and the USDC address. Then read `name()` and `version()` from that chain's USDC contract and use them in the typed data `domain`. If they don't match, the signature is invalid and settlement reverts. Check the chain is listed on the [supported chains page](/guides/supported-chains).

## Notes

- If the customer pays from a smart contract wallet, keep the `bytes signature` overload of `receiveWithAuthorization` used here. USDC checks it with ERC-1271, which only works once the customer's wallet is deployed.
- If you want the merchant account to pay its own gas in USDC instead of sponsoring it, follow [How to use the ERC-20 Paymaster](/guides/how-to/erc20-paymaster/how-to/use-paymaster).

## Limit what you sponsor (optional)

To cap what your API key can sponsor, for example only calls to the USDC contract, create a policy in the [sponsorship policies dashboard](https://dashboard.pimlico.io/sponsorship-policies) and pass its ID as `paymasterContext: { sponsorshipPolicyId }` when you settle. See [How to use sponsorship policies](/guides/how-to/sponsorship-policies).
