# How to batch an approve and a swap into one transaction

This guide shows you how to send a token approval and a swap as one atomic transaction, so the user signs once and the approve and the swap either both execute or both revert. It applies when your users have an ERC-4337 smart account, or an existing EOA that you upgrade with [EIP-7702](#send-from-an-existing-eoa-with-eip-7702), and works with any DEX router or aggregator. If the user connects their own wallet such as a browser extension, see [Send through the user's wallet with EIP-5792](#send-through-the-users-wallet-with-eip-5792) instead.

## Prerequisites

- A Pimlico API key. [Create one](/guides/create-api-key).
- A DEX router or aggregator API that returns swap calldata for a given sell amount and taker address.

```bash [npm]
npm install permissionless viem
```

```bash [pnpm]
pnpm install permissionless viem
```


## Send from an existing EOA with EIP-7702

To batch for users who already have an EOA with funds in it, keep their address by delegating the EOA to a smart account implementation with EIP-7702. Use `to7702SimpleSmartAccount` with EntryPoint 0.8, request the quote with the EOA address as the taker, and attach a signed authorization to the first user operation on each chain. The bundler submits the authorization in the same transaction as the batch, so the user needs no ETH for the upgrade either.

## Send through the user's wallet with EIP-5792

If the user connects an external wallet, your app can't sign an EIP-7702 authorization for it. Request the quote with the wallet's address as the taker, then send the same calls with `wallet_sendCalls` ([EIP-5792](https://eips.ethereum.org/EIPS/eip-5792)) through viem's `sendCalls`. Set `forceAtomic: true` so the wallet rejects the batch instead of splitting it into two transactions, and pass a Pimlico paymaster URL only if the wallet reports `paymasterService` support for the chain.

## Notes

- If your users stay on plain EOAs and you only want to avoid a separate approval per swap, use [Uniswap's Permit2](https://docs.uniswap.org/contracts/permit2/overview) instead: it replaces later approvals with signatures, but still needs one approval transaction per token and ETH for gas. For how Permit2, EIP-2612 permits, EIP-5792 and smart account batching compare, see [Approve and swap in one transaction](/guides/conceptual/approve-and-swap-in-one-transaction).
- If you ship this in a client app, proxy Pimlico requests through your backend so your API key isn't exposed ([guide](/guides/how-to/security/protect-api-keys)).
- To cap sponsored spend per user or sponsor only calls to your router, pass a `sponsorshipPolicyId` ([sponsorship policies](/guides/how-to/sponsorship-policies)).
