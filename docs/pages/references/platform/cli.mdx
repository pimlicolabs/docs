# Pimlico CLI

The Pimlico CLI (`@pimlico/cli`, binary `pimlico`) is a terminal interface to everything the [dashboard](https://dashboard.pimlico.io/) does: credit balance, invoices, usage, supported chains, user operation debugging, sponsorship policies and API keys. It is built for humans in a terminal, for scripts using `--json`, and for coding agents through its [MCP server](#coding-agents-mcp).

## Install

The CLI requires Node.js 20 or later.

```bash
npm install -g @pimlico/cli
```

You can also run any command without installing it:

```bash
npx @pimlico/cli <command>
```

The CLI checks for new versions and updates itself in the background. Set `PIMLICO_NO_AUTO_UPDATE=1` to opt out and run `pimlico upgrade` when you choose to.

## Log in

```bash
pimlico login
```

This opens your browser, where you sign in with your dashboard account and approve the CLI. Once you are logged in, the CLI keeps the session alive on its own; you do not log in again.

Over SSH, inside a container, or wherever a browser cannot be opened, the CLI falls back to a device flow, or you can request it explicitly with `pimlico login --device`. It prints a one-time code and a URL; open the URL on any device, enter the code, and the CLI completes the login by itself.

Tokens are stored in `~/.config/pimlico/credentials.json`, readable only by your user. The CLI never writes tokens to `.env` or any file in your project. Every command acts on the organization that was active when you logged in; personal accounts act on the personal account.

`pimlico whoami` shows the account the CLI is acting as. `pimlico logout` revokes the token on the server and removes it locally.

## Commands

Run `pimlico --help` or `pimlico <command> --help` for every option.

| Command | What it does |
| :------ | :----------- |
| `pimlico init` | Create an API key and write it to `.env` as `PIMLICO_API_KEY` (see [Create API key](/guides/create-api-key)) |
| `pimlico balance` | Balance, unbilled usage and remaining headroom in USD. `--below <usd>` exits with code `2` when headroom is under the threshold |
| `pimlico invoices` | Stripe invoices; `--open` for the ones that still need paying |
| `pimlico usage` | Requests, API credits and sponsored USD over `--last 24h\|7d\|30d`, grouped `--group chain\|key\|day`; `--csv` writes CSV |
| `pimlico chains` | Supported chains with bundler, paymaster and ERC-20 paymaster capability. Works without login |
| `pimlico op <hash>` | Status, transaction hash and event timeline of a user operation |
| `pimlico policies list\|get\|create\|update\|enable\|disable` | Sponsorship policies and their USD caps |
| `pimlico keys list\|get\|create\|rename\|disable` | API keys, identified by their `akey_…` handle |
| `pimlico erc20 tokens` | Tokens the ERC-20 paymaster accepts per chain |
| `pimlico telemetry status\|enable\|disable` | Usage telemetry switch |
| `pimlico upgrade` | Update the CLI now |
| `pimlico mcp` | Start the MCP server (see below) |

An API key is shown exactly once, when it is created. Everywhere else a key is referred to by its handle, such as `akey_7Kd2Qn4vT1`, which grants no access and is safe to paste into tickets, logs and scripts.

## Scripts

Every command accepts `--json` for machine-readable output on stdout; warnings and progress go to stderr, so stdout can be piped straight into `jq`. `--quiet` suppresses the stderr output and `--no-color` disables ANSI colors.

Exit codes:

| Code | Meaning |
| :--- | :------ |
| `0` | Success |
| `1` | Error |
| `2` | Threshold breached (`balance --below`) |
| `3` | Authentication required |
| `75` | Temporarily unavailable or rate limited; retry later |

When the account has open or overdue invoices, every authenticated command prints a one-line warning on stderr. With `--json`, the output carries a top-level `warnings` array instead:

```json
{
  "warnings": [
    {
      "code": "OPEN_INVOICES",
      "count": 2,
      "totalUsd": "4120.00",
      "overdue": true,
      "oldestDueDate": "2026-09-14",
      "url": "https://dashboard.pimlico.io/billing/invoices"
    }
  ],
  "...": "..."
}
```

Warnings do not change the exit code.

The CLI uses your interactive login only. Running it in CI with a stored credential is not supported yet.

## Coding agents (MCP)

`pimlico mcp` runs a [Model Context Protocol](https://modelcontextprotocol.io/) server over stdio using the same login as the CLI. Run `pimlico login` once, and every agent on the machine is authorized as you.

Claude Code:

```bash
claude mcp add pimlico -- npx -y @pimlico/cli mcp
```

Cursor and any other client that supports stdio servers:

```json
{
  "mcpServers": {
    "pimlico": {
      "command": "npx",
      "args": ["-y", "@pimlico/cli", "mcp"]
    }
  }
}
```

Every CLI command is available as a tool named `pimlico_<command>` with underscores between words, for example `pimlico_balance` or `pimlico_policies_create`; only `login`, `logout`, `init`, `telemetry`, `upgrade` and `mcp` are left out. Tools that disable something carry the MCP destructive annotation, so your client asks before running them. Tool results carry the same `warnings` array as `--json` output.

## Telemetry

The CLI sends usage telemetry, described in our [privacy policy](https://www.pimlico.io/privacy), and prints a one-time notice the first time it runs. Turn it off with `pimlico telemetry disable`, or set `PIMLICO_TELEMETRY_DISABLED=1` or `DO_NOT_TRACK=1`.
